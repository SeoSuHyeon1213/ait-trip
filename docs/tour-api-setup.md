# TourAPI 설정

프로젝트 위치: D:\games\ait-trip

1. .env.example을 .env로 복사합니다. 이번 작업에서 .env도 빈 값으로 준비했습니다.
2. TOUR_API_ENDPOINT에 국문 서비스의 기본 URL(KorService2까지, 개별 오퍼레이션 제외)을 입력합니다.
3. TOUR_API_SERVICE_KEY에 일반 인증키(Decoding)를 입력합니다. 서버에서 한 번 인코딩합니다.
4. npm ci 후 npm run dev로 실행합니다. 설정이 둘 다 비어 있거나 하나라도 비어 있으면 Mock 데이터로 시작합니다.
5. 설정 변경 후 개발 서버를 다시 시작합니다. 값이 모두 있으면 실제 API를 사용하며 인증 실패를 샘플 데이터로 숨기지 않습니다.

엔드포인트와 인증키의 초기 값은 공백입니다. VITE_ 접두사로 인증키를 만들지 않습니다. 실제 .env는 Git에서 제외됩니다.

개발/미리보기에서는 Vite 서버가 /api를 처리합니다. npm run build 후 npm start는 dist와 API를 함께 제공하는 별도 Node 서버입니다. Node 22 이상을 사용하세요.

앱인토스 번들은 서버 코드를 포함하지 않습니다. 실제 토스 앱 출시에는 별도 HTTPS 서버 배포와 /api 주소 연결(허용된 API 서버 또는 프록시)이 필요합니다. 로컬 서버 구현만으로 토스 도메인에 /api가 만들어지는 것은 아닙니다.

목록은 areaBasedList2, 상세는 detailCommon2/detailIntro2/detailImage2, 지역/분류는 ldongCode2/lclsSystmCode2를 사용합니다. 페이지 이동은 서버 조회 페이지를 바꿉니다. 전라는 두 시도의 각 페이지 결과를 합쳐 최대 40곳을 표시할 수 있습니다.

기분별 테마는 src/config/moodThemes.mjs에서 관리합니다. 휴식은 자연공원(NA04), 기분 전환은 하천·해양 경관(NA02), 새로운 경험은 전시시설(VE07), 함께는 테마공원(VE02)을 조회합니다. lclsSystm1과 lclsSystm2를 함께 전달하며 페이지·지역 조건을 유지합니다. 테마에 맞는 결과가 없으면 다른 테마로 대체하지 않고 빈 목록을 안내합니다. 분위기나 혼잡도는 별도 검증하지 않은 분류 기반 추천입니다.

API 오류는 결과 코드와 XML 인증 오류를 확인합니다. 서버는 5분 응답 캐시와 10초 제한시간을 사용하고 오류 원문/인증키를 브라우저에 보내지 않습니다. 일반 조회·수신 데이터 파싱은 자동 테스트로 검증하며 실제 인증 성공은 키 입력 후 확인해야 합니다.

사진은 HTTPS인 경우만 표시(관광공사 tong.visitkorea.or.kr의 HTTP 사진 주소는 HTTPS로 전환 시도)하고 누락·실패 시 SVG를 표시합니다. Type3 이미지를 자르지 않도록 contain으로 표시합니다. 정보/사진 출처를 화면에 안내합니다. 숙박은 이용시간 위치에 체크인 시간을 표시하며 공통 요금이 없는 유형은 미제공으로 표시합니다.

토스 앱 연결용 배포 과정과 VITE_API_BASE_URL 설정은 [Render 배포 안내](render-deployment.md)를 참고하세요. 출시용 빌드는 실제 HTTPS 서버 주소가 있어야 실행할 수 있습니다.
